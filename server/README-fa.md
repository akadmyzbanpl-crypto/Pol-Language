# آموزشگاه زبان پل — نسخه ۰.۴ — طراحی سرمه‌ای و طلایی

این بسته شامل نسخه متصل به سرور و صفحه HTML مستقل با همان سبک طراحی است. تمرکز دوره‌ها فقط زبان انگلیسی است. طراحی براساس تصاویر مرجع کاربر، با زمینه سرمه‌ای #140f27، بخش‌های کرم #f3eedf، دکمه‌های طلایی و فونت محلی IBM Plex Sans Arabic بازطراحی شده است. لوگوی اصلی آموزشگاه حفظ شده است.

## سریع‌ترین راه دیدن طراحی

در پوشه بالاتر، `public_html/index.html` را باز کنید. نسخه HTML مستقل، جست‌وجوی دوره‌ها، تعیین سطح اولیه و نمونه پنل‌ها را نمایش می‌دهد. راهنمای مخصوص هاست و اتصال صفحه HTML به سرور در `GUIDE-fa.html` است. پوشه `deploy` برای انتشار هم‌زمان سایت اصلی و پنل روی دو نام دامنه آماده شده است. دستورهای Docker زیر، روش جداگانه انتشار فقط بخش سرور را توضیح می‌دهند.

## اجرای واقعی روی ویندوز

۱. Python 3.12 یا جدیدتر را نصب کنید.
۲. در پوشه `server` فایل `start-windows.bat` را اجرا کنید. نصب وابستگی‌ها در اولین اجرا اینترنت می‌خواهد.
۳. برنامه پایگاه داده و داده‌های نمونه را می‌سازد. نام کاربری و رمزهای تصادفی اولیه در پنجره فرمان نمایش داده می‌شود. آن‌ها را برای آزمایش یادداشت کنید؛ حساب واقعی آموزشگاه نیستند.
۴. نشانی `http://127.0.0.1:8000` را در مرورگر باز کنید و پنجره فرمان را باز نگه دارید.
۵. حساب‌های `demo_student`، `demo_teacher` و `demo_admin` سه نقش را نشان می‌دهند. در اجرای دوباره، رمز حساب موجود تغییر نمی‌کند. برای تغییر رمز آزمایشی، در محیط مجازی و با `POL_DEBUG=1` از `python manage.py changepassword demo_admin` استفاده کنید.

رمزهای محیط ساخت و پایگاه داده آزمایشی در بسته قرار نگرفته‌اند. رمزها در اجرای شما تازه ساخته می‌شوند.

## اجرای محلی لینوکس یا macOS

در پوشه server:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python run-local.py
```

اجرای محلی مخصوص بررسی و توسعه است. برای سرور عمومی از مراحل زیر استفاده کنید.

## استقرار روی سرور و دامنه خودتان

نسخه سرور یک برنامه Python/Django است. هاست صرفاً PHP برای این بسته کافی نیست. فایل‌های Docker، Docker Compose و Caddy برای سرور لینوکسی دارای Docker آماده شده‌اند. هنوز هیچ دامنه یا سروری خریداری یا متصل نشده است.

۱. پوشه server را روی سرور منتقل کنید.
۲. رکورد A دامنه یا زیردامنه را به IP سرور وصل کنید. پورت‌های ۸۰ و ۴۴۳ باید برای وب در دسترس باشند. برنامه داخلی روی ۸۰۰۰ فقط در شبکه Docker است و پورت عمومی ندارد.
۳. فایل `.env.example` را با نام `.env` کپی کنید.
۴. مقدار `POL_DOMAIN`، `POL_PUBLIC_BASE_URL`، `POL_ALLOWED_HOSTS` و `POL_CSRF_ORIGINS` را با دامنه واقعی و HTTPS تنظیم کنید.
۵. یک کلید تصادفی جدید بسازید:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(64))"
```

خروجی را فقط در `POL_SECRET_KEY` قرار دهید. `POL_DEBUG=0` و `POL_DEMO=0` باقی بمانند. فایل `.env` را عمومی نکنید و در پوشه عمومی وب قرار ندهید.

۶. راه‌اندازی:

```bash
docker compose up -d --build
docker compose exec web python manage.py createsuperuser
docker compose exec web python manage.py check --deploy
```

Caddy پس از اتصال صحیح دامنه، HTTPS را مدیریت می‌کند. درخواست‌ها به برنامه منتقل می‌شوند. `POL_TRUST_PROXY=1` برای همین شبکه بسته و پراکسی همراه بسته است؛ پورت برنامه را مستقیماً عمومی نکنید.

۷. با حساب مدیر ارشد در `/system-admin/` وارد شوید. در قسمت کاربران، نقش آموزشی حساب را «مدیر» قرار دهید. مدیر ارشد حتی قبل از این تغییر هم از نظر دسترسی مدیر است. حساب‌های دیگر با ثبت‌نام عادی دانشجو می‌شوند؛ مدیر می‌تواند در پنل سایت نقش استاد یا مدیر تعیین کند.
۸. دوره‌های واقعی، مدرس، شهریه، ظرفیت و زمان را وارد کنید. برای هر دوره جلسه بسازید و لینک کلاس، ضبط و منابع را ثبت کنید. هنگام نصب عمومی، دستور `seed_demo` را اجرا نکنید؛ در حالت تولید عمداً غیرفعال است.
۹. پیش از فروش عمومی، یک ثبت‌نام و پرداخت کم‌مبلغ مورد تأیید آموزشگاه را با حساب پذیرندگی واقعی از ابتدا تا ورود به کلاس بررسی کنید. این آزمایش مالی در محیط ساخت انجام نشده است.

Docker image و HTTPS روی سرور بیرونی در این محیط اجرا یا تأیید نشده‌اند؛ فایل‌های استقرار و راهنما تحویل شده‌اند. تست‌های منطق و دسترسی سرور و ارتباط فهرست عمومی اجرا شده‌اند؛ فایل‌های HTML و دارایی‌های محلی نیز بررسی شده‌اند. تصاویر تولیدشده جداگانه بازبینی بصری شده‌اند. مرورگر این محیط اجازه باز کردن نشانی محلی و فایل محلی را نداد؛ نمایش نهایی صفحه در دسکتاپ و موبایل باید با پیش‌نمایش بسته یا اجرای محلی بررسی شود.

## پایگاه داده و پشتیبان‌گیری

پایگاه داده SQLite در مسیر `data/pol.sqlite3` با اجرای migrate ساخته می‌شود. ساختار کامل در `academy/migrations` قرار دارد. volume نام‌دار `pol-data` داده‌ها را بین ساخت‌های Docker حفظ می‌کند. از `docker compose down -v` روی محیط دارای اطلاعات استفاده نکنید، چون volumeها را حذف می‌کند.

پشتیبان سازگار از پایگاه داده:

```bash
docker compose exec web python manage.py backup_database /app/data/pol-backup-2026-09-12.sqlite3
docker compose cp web:/app/data/pol-backup-2026-09-12.sqlite3 ./pol-backup-2026-09-12.sqlite3
```

برای هر نسخه پشتیبان نام تازه انتخاب کنید و آن را خارج از سرور نگه دارید. پشتیبان حاوی اطلاعات حساب‌هاست. بازیابی را ابتدا روی محیط جداگانه آزمایش کنید. استقرار فعلی برای یک نمونه برنامه و بار محدود در نظر گرفته شده است؛ چند سرور هم‌زمان و بار زیاد نیاز به طراحی پایگاه داده و زیرساخت متناسب دارند. آزمون بار انجام نشده است.

## اتصال‌های خارجی و وضعیت آن‌ها

### گوگل

مقادیر `GOOGLE_CLIENT_ID` و `GOOGLE_CLIENT_SECRET` را در `.env` تنظیم کنید. در Google Cloud یک OAuth client از نوع Web بسازید و redirect URI دقیق زیر را با دامنه خودتان ثبت کنید:

`https://YOUR-DOMAIN/auth/google/callback/`

تنظیم صفحه رضایت و وضعیت انتشار برنامه در حساب گوگل لازم است. پیاده‌سازی با Authlib، جریان authorization code و PKCE و بررسی state و توکن هویت است. حساب گوگل جدید به نقش دانشجو ساخته می‌شود؛ ایمیل باید تأییدشده باشد. ایمیل حساب موجود به‌صورت خودکار به حساب گوگل وصل نمی‌شود تا اتصال ناخواسته رخ ندهد؛ کاربر موجود با رمز خودش وارد می‌شود. کلیدهای گوگل در فایل‌های مرورگر قرار نمی‌گیرند. ورود واقعی گوگل بدون حساب تنظیم‌شده آزمایش نشده است.

### پرداخت

آداپتور قابل تنظیم زرین‌پال در `academy/payments.py` آماده است. `ZARINPAL_MERCHANT_ID` را پس از فعال‌شدن پذیرندگی وارد کنید. مبالغ داخل سامانه تومان و درخواست درگاه ریال است؛ تبدیل در سرور انجام می‌شود. مسیر callback برابر `/payment/callback/` است. موفقیت صرفاً بر اساس برگشت مرورگر ثبت نمی‌شود؛ پاسخ verify درگاه لازم است. بازگشت تکراری باعث ثبت‌نام دوباره نمی‌شود.

تا قبل از تنظیم پذیرندگی، پرداخت آنلاین غیرفعال است. سفارش ذخیره می‌شود و مدیر فقط پس از بررسی رسید پرداخت خارج از سایت می‌تواند آن را تأیید کند. اگر بعد از پرداخت ظرفیت پر باشد، سفارش در وضعیت «نیازمند بررسی ظرفیت» می‌ماند و ثبت‌نام اضافه ساخته نمی‌شود. تعیین کلاس جایگزین و بازپرداخت در این وضعیت دستی است. در این نسخه بازپرداخت خودکار، تسویه بانکی و اتصال حسابداری پیاده نشده‌اند.

این اتصال با پاسخ ساختگی در تست‌ها بررسی شده، نه با تراکنش واقعی. تطبیق نهایی حساب پذیرندگی، واحد مبلغ، callback و خطاها باید پیش از فعال‌کردن فروش انجام شود. انتخاب زرین‌پال قابل تعویض است و به معنی انتخاب یا افتتاح حساب از طرف آموزشگاه نیست.

### پیشنهاد تمرین با هوش مصنوعی

`OPENAI_API_KEY` و `OPENAI_MODEL` را مطابق حساب مجاز آموزشگاه تنظیم کنید؛ مدل پیش‌فرض تحمیل نشده است. پس از فعال‌سازی، دانشجو می‌تواند در صفحه نتیجه آزمون با رضایت خودش، سطح پیشنهادی و درصد پاسخ صحیح را برای تهیه برنامه تمرین هفت‌روزه ارسال کند. نام، ایمیل، پاسخ‌های خام و مشخصات حساب ارسال نمی‌شوند. از Responses API و `store=false` استفاده می‌شود؛ این گزینه به معنی نبود همه لاگ‌های سرویس‌دهنده نیست.

برای هر نتیجه یک درخواست و برای هر حساب حداکثر سه تلاش در روز در نظر گرفته شده است. هزینه و دسترسی منطقه‌ای/حساب سرویس باید هنگام فعال‌سازی بررسی شود. هیچ کلید یا اعتبار خریداری نشده و درخواست واقعیِ هزینه‌دار ارسال نشده است. خروجی مدل فقط پیشنهاد تمرین است و نمره یا ثبت‌نام را تغییر نمی‌دهد.

### کلاس آنلاین

سایت خود موتور تماس تصویری یا ضبط ندارد. استاد لینک HTTPS سرویس کلاس و لینک ضبط را ثبت می‌کند و فقط اعضای مجاز دوره آن را می‌بینند. کنترل درخواست صحبت و چت مربوط به فضای داخل سایت است، نه میکروفن سرویس ویدئویی. برای محتوای پولی، محدودیت دسترسی و اعتبار لینک‌ها در سرویس میزبان ویدئو نیز باید تنظیم شود؛ سایت امکان جلوگیری از کپی لینک دائمی سرویس بیرونی را ندارد.

## تعیین سطح

بانک پرسش‌ها برای این پروژه نوشته شده است. نتیجه A1 تا C1 یک پیشنهاد اولیه مبتنی بر پاسخ‌هاست و آزمون اعتبارسنجی‌شده CEFR یا گواهی مهارت نیست. نمره از سمت مرورگر پذیرفته نمی‌شود. استاد باید مهارت گفتاری، شنیداری و نوشتاری و کفایت بانک سؤال را پیش از استفاده آموزشی رسمی بررسی کند.

## بررسی‌های انجام‌شده

۱۷ آزمون خودکار Django موفق (شامل ۳ آزمون فهرست عمومی و CORS):
- رندر صفحات عمومی و پنل‌ها؛ ثبت‌نام و جلوگیری از ارتقای نقش هنگام ثبت‌نام.
- جداسازی پرونده، سفارش، تیکت و کلاس کاربران و استادان.
- حفاظت CSRF و جلوگیری از تغییر وضعیت با GET.
- قیمت سمت سرور، ثبت‌نام یکتا، ظرفیت و تأیید تکراری پرداخت.
- تعیین سطح سمت سرور و بی‌اثرشدن ارسال دوباره همان مرحله.
- دامنه مجاز حضور‌وغیاب، ثبت نمره و بازه ۰ تا ۱۰۰.
- دامنه پیام گروهی، escaping متن و کنترل چت توسط استاد.
- محدودیت تلاش ورود؛ غیرفعال‌بودن گوگل بدون تنظیمات.
- آداپتور درگاه و هوش مصنوعی با پاسخ Mock، رضایت کاربر و حداقل‌سازی اطلاعات ارسالی.

`manage.py check --deploy` با تنظیمات تولید نمونه بدون مسئله گذشت. این بررسی جای آزمون بار، ارزیابی نفوذ، بررسی بصری یا تست سرویس‌های واقعی را نمی‌گیرد. محدودکننده ورود بر حساب و آدرس اتصال اعمال می‌شود؛ در تنظیم پراکسی همراه بسته، سقف آدرس بین کاربران پراکسی مشترک است و در مقیاس بالاتر باید با شناسه IP قابل اعتماد و محدودکننده لبه تنظیم شود.

برای اجرای دوباره تست‌ها:

```bash
POL_DEBUG=1 python manage.py test academy
```

## تغییرات طراحی نسخه ۰.۳

- سربرگ کرم با لوگوی پل، دکمه طلایی تعیین سطح و دسترسی ورود/ثبت‌نام.
- بخش معرفی تمام‌عرض سرمه‌ای با بافت نقطه‌ای، تصویر پل نورانی و کتاب و متن طلایی.
- کاتالوگ روی زمینه کرم و کارت تأکیدی آیلتس با زمینه تیره.
- بخش معرفی آموزگاران و کارت دوره پیشنهادی با تصویر فضای کلاس.
- بخش درباره پل و پرسش‌های متداول با لینک‌های درون‌صفحه فعال.
- هماهنگی ظاهر پنل‌ها، فرم‌ها، جدول‌ها، پیام‌ها و منوی کناری با رنگ‌بندی جدید.
- نسخه آفلاین شامل یک نوار راهنماست؛ نوار تکراری نسخه قبلی حذف شده است.

تصاویر اصلی پل، کلاس و پرتره‌ها با ابزار تصویرسازی ساخته شده‌اند. تصویر کلاس نمای واقعی آموزشگاه نیست. چهار پرتره ساختگی و پروفایل‌های نمونه تنها با POL_DEMO=1 نمایش داده می‌شوند. در حالت واقعی، نام استادان ثبت‌شده با نماد حرف اول نام نمایش داده می‌شود؛ افزودن عکس و شرح حال واقعی نیازمند دریافت اطلاعات آموزشگاه است.

آمار فرضی سابقه، درصد رضایت یا تعداد زبان‌آموزانِ تصویر مرجع به سایت منتقل نشده است. تعداد دوره‌های صفحه اصلی از داده‌های واقعی سامانه خوانده می‌شود. تمرکز دوره‌ها مطابق PRD همچنان انگلیسی است.

فایل‌های تصاویر در server/static/pol/:
- bridge-hero.webp
- classroom-scene.webp
- faculty-grid.webp — چهار پرتره در یک تصویر؛ کادرها با CSS نمایش داده می‌شوند.
- asset-prompts.json — متن دقیق درخواست‌های تصویرسازی با ابزار داخلی image_gen.

هیچ تصویر مرجعِ دارای نوشته یا نوار ابزار مرورگر به‌عنوان تصویر نهایی داخل سایت قرار نگرفته است.

## فهرست عمومی برای نسخه HTML

مسیر `GET /api/public/catalog/` فقط دوره‌های منتشرشده و نام نمایشی مدرس فعال آن‌ها را برمی‌گرداند. ایمیل، شناسه ورود، سفارش و اطلاعات دانشجو در پاسخ وجود ندارد. برای صفحه اصلی جدا از پنل، `POL_SITE_ORIGIN` را برابر مبدأ دقیق HTTPS سایت اصلی قرار دهید. CORS فقط برای همان مبدأ و بدون کوکی اجازه داده می‌شود. این مسیر هیچ اطلاعاتی ثبت نمی‌کند. نسخه HTML پس از تنظیم `backendOrigin` این داده‌ها را دریافت می‌کند؛ شهریه نهایی و ظرفیت همیشه در صفحه ثبت‌نام سمت سرور کنترل می‌شوند.
